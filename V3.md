# v3 — what we implemented and what it showed

v3 implements the three prerequisites identified at the end of v2, then validates them on
five related articles. Nothing about the pipeline's shape changed — see
[`HOW_IT_WORKS.md`](HOW_IT_WORKS.md) for that. This is about making a full-act run
**correct** and, more importantly, **judgeable**.

Run: `OUT=out_v3 ARTICLES=art_5,art_6,art_8,art_9,art_16 ./run_v2.sh`
Cost: **6 LLM calls, 181 s, 27.3k prompt + 25.1k completion tokens.**

---

## The three changes

### 1. Overlap removal — the bug that would have corrupted a full run

**The problem.** `--articles all` selected both chapters and the articles inside them.
`chp_3` is 108,031 characters and physically contains Articles 8–15, which were also
selected individually. Nearly half the selected bytes were duplicated content, and each
duplicate would have been formalised twice under two different vocabularies.

Id prefixes cannot detect this: `chp_3` and `art_9` are *sibling* fragments, so no string
comparison relates them. What does work is the `start`/`end` character offsets every unit
already carries. `chp_3` spans 275337–383368; `art_9` spans 284373–288543. Containment is
then exact arithmetic.

**The rule.** For each container, measure how much of it the contained units actually cover:

| coverage | action | why |
|---|---|---|
| ≥ 60% | drop the **container** | the fine-grained articles are better input and already cover it |
| < 60% | keep the container, drop its **parts** | dropping it would lose text |

That threshold is not cosmetic. Measured coverage:

```
chp_2       100%  ─┐
chp_12      100%   │
chp_6        96%   ├─ dropped: articles cover them
chp_3        95%   │
chp_5        86%   │
chp_9/sec_3  82%   │
chp_9/sec_5  78%   │
chp_7        65%  ─┘
chp_1         6%  ←── KEPT: the corpus carries only four small fragments of
                        Articles 1–4, so dropping Chapter I would lose the rest
```

Either branch yields a partition, so no character is processed twice.

**Effect on a full run:**

| | before | after |
|---|---|---|
| provisions | 154 | **136** |
| characters | 661,453 | **392,638** |
| residual containment pairs | (unmeasured) | **0** |
| residual span overlaps | (unmeasured) | **0** |

41% of the input was duplication. It also caught four overlaps I had not spotted:
`anx_8/sec_1`, `anx_8/sec_3`, `art_36/par_9`, `art_62/par_1`.

### 2. A naming grammar in the Phase B prompt

The frozen signature makes independent calls agree on vocabulary Article 3 *has a word
for*. It does nothing for concepts each article must invent — and that is where v2's
instability lived (`permitted_rrbis_use` vs `permitted_use_rt_rbi`).

So the prompt now specifies how invented names must be built:

```
MODALITY    prohibited_<thing>  permitted_<thing>  required_<thing>  exempt_<thing>
PURPOSE     objective_<purpose>
PROPERTY    <adjective>(X)
ACT/EVENT   <verb>_<object>(A, B)
DUTY        must_<verb>(Actor, X)
CONDITION   <noun>_applies(X)
```

Plus three constraints that matter more than the forms:

- **Name the subject matter, never the article number.** `prohibited_social_scoring`, not
  `prohibited_art_5_1_c` — otherwise two articles discussing one concept can never agree.
- **Never abbreviate.** `remote_biometric_identification`, not `rbi`. Two calls will not
  invent the same abbreviation, but they will agree on the full words.
- **Fixed word order**, singular, British spelling.

The prompt states *why*: you are one of many calls that cannot see each other, and a
mismatch produces a rule that never fires and never errors.

### 3. A cross-file consistency check — the one that makes scale judgeable

Every other check in `lint.py` is per-file. Five provisions can each be perfectly
internally consistent — clean syntax, link integrity 1.0, no vacuous negations — and still
fail as one ontology because call 1 and call 2 named the same concept differently.

**A per-file linter scores that identically to a good result.** Without this check, a
136-provision run cannot be distinguished from a good one, which is exactly why it had to
exist before the full run.

It measures, over predicates the calls *invented* (signature predicates are excluded —
agreement on those proves nothing):

- **fragmentation** — share used in only one file
- **alias candidates** — same concept under two names, by identical gloss or ≥0.6 token overlap
- **grammar violations** — article/annex numbers baked into a name
- **modality-prefixed** — descriptive only

## Results on the five articles

Articles 5, 6, 8, 9 and 16 — chosen because they share concepts, so drift surfaces fast.

| check | result |
|---|---|
| `swipl` consult | **clean** — 0 errors |
| Link integrity | **1.0** — 109/109 body goals resolve |
| Vacuous negations | **0** |
| Arity collisions | **0** |
| Provenance | **43/43** rule heads traceable |
| Reference graph (chunk-level) | **P 1.0 · R 0.85 · F1 0.919** |
| Singleton-variable warnings | 37 — see below |
| **Invented predicates** | **76** |
| **Shared across files** | **2** |
| **Fragmentation** | **0.974** |
| **Grammar violations** | **2** |
| **Alias candidates** | **8** |

### What worked

**The concept that had to converge, converged.** `high_risk_ai_system` is the organising
idea of Chapter III, and all four of Articles 6, 8, 9 and 16 independently used that exact
name. No call saw another's output. That is the mechanism working.

**Article 5's prohibitions came out uniformly.** All eight follow the grammar:

```
prohibited_biometric_categorisation_ai_system
prohibited_emotion_inference_ai_system
prohibited_exploit_vulnerabilities_ai_system
prohibited_facial_recognition_database_creation_ai_system
prohibited_real_time_remote_biometric_identification_in_public_spaces
prohibited_risk_assessment_ai_system
prohibited_social_scoring_ai_system
prohibited_subliminal_manipulative_ai_system
```

Note `..._real_time_remote_biometric_identification_...` spelled out in full — the
"never abbreviate" rule held, where v2 produced `rt_rbi`.

**Structural quality held at 5× the scope.** Link integrity stayed at 1.0 across 109 body
goals, provenance at 100%, and still zero vacuous negations.

### What did not work

**Fragmentation is 0.974 — but that number needs interpreting, and I would rather say so
than let it read as a grade.** It counts invented predicates used in only one file. Much
of that is correct: `prohibited_social_scoring_ai_system` *belongs* to Article 5 and
nowhere else. Fragmentation is an **upper bound on the problem, not a defect count**.

The reviewable signal is the alias list, and it does show real drift:

```
required_compliance ~ required_compliance_with_requirements
required_compliance ~ required_ensuring_compliance
required_compliance ~ required_accessibility_compliance     ← one concept, four names
must_publish_annual_report ~ must_submit_annual_report      ← genuine synonym pair
required_risk_management_system ~ risk_management_system     ← duty vs entity, arguably fine
required_quality_management_system ~ required_risk_management_system   ← FALSE positive
```

So of 8 candidates, roughly 5 are genuine, 1 is a clear false positive, and 2 are
arguable. Token overlap cannot distinguish "quality" from "risk" management, so this list
is **candidates for human review, not a defect count**.

**Two grammar violations** — `annex_3_ai_system` and `covered_by_annex1` bake a document
reference into the name, which the prompt explicitly forbids.

**37 singleton-variable warnings.** From rules like:

```prolog
prohibited_subliminal_manipulative_ai_system(S) :-
    (   placing_on_market(P, S) ; putting_into_service(D, S) ; use_ai_system(U, S) ),
```

`P`, `D`, `U` are each used once. Semantically fine — the provision doesn't care *who* —
but the Prolog idiom is `_P`. Cosmetic, one prompt line to fix.

### Three linter bugs found and fixed during this run

Worth recording, because each would have distorted the full run's numbers:

| bug | effect | fix |
|---|---|---|
| `pred`, `gloss`, `source` scraped as predicates | inflated invented count 76→79, polluted "shared" | exclude declaration syntax |
| `permitted_x` flagged as an alias of `prohibited_x` | the new grammar would have *increased* the alias count, since it puts identical stems on opposite modalities | skip pairs whose modality differs |
| `grammar_rate` counted modality prefixes only | reported 0.544 "conformance" when un-prefixed PROPERTY/ACT forms (`causes_significant_harm`) are grammar-*compliant* | replaced with a real, checkable violation |

Reference scoring also gained v1's attribution-free variant: Article 5's call attributed
references to the sub-provision carrying them (`...#art_5/par_2`), which is *better*
provenance but scored as a miss. Chunk-level recall is 0.85; strict is 0.783.

## Is this ready for the full act?

**Revised after the fact.** This recommendation assumed the selected 136 provisions
cover the act. They do not — see
[Post-run finding](#post-run-finding-the-reference-closure-is-not-an-index-of-the-act)
below. Read that before running the full act.

**The infrastructure: yes.** Overlap is gone and verified at zero, the run is 136
provisions / 393k chars, and — decisively — a full run is now *measurable*. Before change
3 there was no way to tell a connected 136-provision ontology from a fragmented one.

**The namespace: partially.** The grammar demonstrably helped. `high_risk_ai_system`
converged across four independent calls, Article 5's eight prohibitions are uniform, and
abbreviations stopped. But the `required_compliance` family shows one concept acquiring
four names across five articles, and that will scale.

**My recommendation: run it.** Two reasons. The remaining drift is *concentrated and
visible* — 5 genuine aliases over 76 predicates, all in generic administrative concepts
("compliance", "annual report") rather than substantive legal ones. And the failure is
**diagnosable after the fact**: the alias list from a 136-provision run tells you exactly
which concepts need pinning, which is far better evidence for a second signature layer
than extrapolating from five articles.

Estimated cost: ~137 calls, **30–45 min**, £0. Grounded in v1's comparable run (285 calls,
26.6 min at the same concurrency), not guessed.

**What I would not do** is claim the result is a finished ontology. It will be a
structurally sound, fully traceable, queryable rule base with a known and measured naming
inconsistency in its administrative vocabulary. That is a genuine proof of work for the
pipeline. It is not yet a production artefact, and the alias list is the honest statement
of what remains.

### If you want the namespace tightened first

The cheapest next step is a **second signature layer**: run Phase B over all 136
provisions, collect every invented predicate, have one LLM call merge the aliases into a
canonical list, freeze that as `signature_2.pl`, and re-run Phase B against the union.
Two full passes instead of one — about 90 minutes — and it removes the drift by
construction rather than by hoping the grammar holds.

That is the natural v4, and the full run is the input it needs.

## Post-run finding: the reference closure is not an index of the act

Found while re-examining the 60% threshold, after the five-article run was complete.
This is a **selection** defect, not a generation defect, and it is the strongest argument
so far for a structural change rather than another prompt or linter refinement.

### The defect

`select_provisions` builds its work list from `units/`, which is a **reference closure**:
a unit file exists for a provision only if something cited it. The act's own structure is
never consulted. So the pipeline's notion of "what exists in the act" is really "what the
act cross-references", and those are not the same set.

The act has **113 articles**. 99 have at least one unit file. **14 have none at all**:

```
art 1, 4, 32, 35, 39, 42, 45, 64, 65, 85, 87, 88, 89, 113
```

Whether an article with no unit survives depends entirely on whether its chapter
container happened to be kept by the coverage threshold:

| articles | chapter | chapter coverage | fate |
|---|---|---|---|
| 1, 4 | `chp_1` | 6% → container **kept** | covered by the container |
| 32, 35, 39, 42, 45 | `chp_3` | 95% → container **dropped** | **lost** |
| 64, 65 | `chp_7` | 65% → container **dropped** | **lost** |
| 85, 87, 88, 89 | `chp_9` | 82% / 78% (sections) → **dropped** | **lost** |
| 113 | `chp_13` | no chapter unit exists | **lost** |

**12 of 113 articles are in no processed unit.** They are not formalised, not linted, and
not visible in any report — the pipeline cannot distinguish "this article yielded no
rules" from "this article was never shown to the model".

### Why the mechanism is perverse

The threshold measures how much of a container its *referenced* parts cover. The better
the closure covers a chapter, the more certainly the container is dropped — and the
unreferenced articles inside it go with it.

Chapter III is the clearest case: 48 units covering 95% of it, so the container is dropped
as redundant, and Articles 32, 35, 39, 42 and 45 disappear precisely *because* their
neighbours were well referenced. **The loss is worst where coverage looks best.** Chapter I
retains Articles 1 and 4 only by the accident of being badly covered (6%).

### "Unreferenced" does not mean "unimportant"

This was the hope worth testing, and it does not hold. Reference closure measures position
in the citation graph. An article is absent when no other provision needs to point *at*
it, which correlates with being self-contained, not with being insignificant.

```
art_32     461 chars   Presumption of conformity ... relating to notified bodies
art_35     455 chars   Identification numbers and lists of notified bodies
art_39     432 chars   Conformity assessment bodies of third countries
art_42     761 chars   Presumption of conformity with certain requirements
art_45   1,769 chars   Information obligations of notified bodies
art_64     221 chars   AI Office
art_65   2,854 chars   Establishment and structure of the European AI Board
art_85     569 chars   Right to lodge a complaint with a market surveillance authority
art_87     305 chars   Reporting of infringements and protection of reporting persons
art_88     659 chars   Enforcement of obligations of GPAI model providers
art_89     912 chars   Monitoring actions
art_113    604 chars   Entry into force and application
```

In fairness: some are thin for rule extraction. Articles 32 and 42 are
presumption-of-conformity provisions that are nearly pure cross-reference; Article 64 is
221 characters.

**Article 113 is the decisive counterexample.** It governs *when every other obligation in
the act applies* — "It shall apply from 2 August 2026. However: (a) … shall apply from
2 February 2025; … (c) … shall apply from 2 August 2027". It is dense with outgoing
references and has zero incoming ones, because a commencement provision is structurally
terminal: nothing needs to cite it. By the closure's criterion it does not exist, and it
conditions the applicability of everything that does. Articles 65 and 85 are substantive
in their own right.

So the correlation between "unreferenced" and "unimportant" is weak, and the exceptions
are load-bearing.

### This is not a data problem

Nothing is missing from the corpus. `celex:32024R1689%2Foj.xml` carries the complete act —
628,255 characters, `<ref>` markup intact. Every lost article's text is sitting in it.

Units provide two conveniences: pre-cut provision boundaries and canonical ids for
provenance. They are an **index**, not an information source. Using the index as the
definition of what exists is the error.

The alternative is already in production: Article 3 is not in the closure at all, so
`slice.py` cuts its 68 definitions directly out of the whole-act unit, preserving refs,
asserting an expected item count that fails loudly if the corpus shifts. Phase A has
never depended on the closure.

### The earlier objection to "just use the whole act" was about something else

The argument against feeding the whole act was about **call granularity** — a
108k-character chapter in one LLM call produces an unusable blob, and it breaks the
property that each Phase B call is a pure function of `(provision, signature)`.

That is independent of **which spans to process**. A work list can be enumerated top-down
from the act's structure while still making one call per article. Conflating the two
decisions is what produced this gap: the closure was adopted as the index of what exists,
when it was only ever an index of what was cited.

### Options

| | change | cost | generalises? |
|---|---|---|---|
| **a** | **Report the gap.** Regex the act's `Article N` headings, diff against what selection covers, print the lost list. No behaviour change. | ~15 lines, deterministic | yes |
| **b** | Add slice specs for the 12 missing articles. | 12 rows in `SPECS`, manual | no — redone per act |
| **c** | **Derive the work list from the act's structure.** One work unit per article heading; use the unit file where one exists, slice the span where it does not. | touches `select_provisions` + `slice` | yes |

Under (c) coverage is complete by construction and the 60% threshold stops being a
text-loss decision — it only decides granularity, which is what it was meant to decide.

**(a) is worth doing immediately and independently of the rest**: the loss is currently
invisible, and the tradeoff cannot be reasoned about while that is true. It is the same
visibility pattern as the Phase A coverage check added after the v3 signature silently
dropped definitions 29–34.

**(b) is not recommended** — it encodes this act's gaps as constants and would be redone
for the next regulation.

### Consequence for the full-act run

The "run it" recommendation above still holds for what it was measuring — namespace drift
at scale — but a full run executed today would formalise **101 of 113 articles while
reporting nothing about the other 12**. Any coverage claim made from it would be wrong,
and silently so.

Either land (a) first so the run's limits are stated in its own output, or land (c) first
so the limitation does not exist. Given that this is the second finding in a row where the
pipeline's reports could not see what the pipeline had dropped — the signature's missing
definitions, and now the selection's missing articles — the case for the larger shift (c)
is stronger than the cost of doing it.
